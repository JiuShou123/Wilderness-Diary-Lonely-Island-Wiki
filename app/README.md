# 荒野日记：孤岛 · 本地 Wiki 网站

Terraria Wiki 风格的**树状结构**游戏百科：门户式首页 + 分类枢纽页 + 每个条目独立页面 + 目录导航 + 全站检索。
纯前端实现（HTML / CSS / JavaScript），零依赖、无后端、可完全离线使用。

> 内容规模：**559 个页面**（43 个分类枢纽 + 516 个条目页）、约 47.8 万字、2549 条站内链接（站内链接校验 0 死链）。

---

## 一、内容组织结构（树状）

```
wiki/
├── README.md                        首页（门户：英雄区 + 分类卡片导航）
├── 01-游戏概览/
│   ├── 游戏简介.md / 背景故事.md      （综述文章）
│   ├── 角色/        角色一览 + 5 个角色条目页
│   ├── 奇遇/        奇遇一览 + 19 个奇遇条目页
│   ├── NPC/         NPC一览 + 6 个 NPC 条目页
│   └── 逃离方式/     逃离方式一览 + 11 个方式条目页
├── 02-核心机制/     生存系统 / 战斗系统 / 科技系统 / 挑战模式 / 建筑与制造 / 钓鱼系统 / 陷阱系统
│   ├── 天赋/        天赋一览 + 23 项天赋条目页
│   ├── 挑战主题/     主题一览 + 13 个主题条目页
│   ├── 小游戏/       小游戏一览 + 5 个玩法条目页
│   └── 建筑/        建筑一览 + 20 余个建筑条目页
├── 03-物品/         物品总览 + 11 个分类（材料/食物/药品/近战武器/远程武器/
│                    投掷武器/防具/工具/鱼类/特殊道具/活动物品）+ 270+ 物品条目页
├── 04-生物/         生物总览 + 13 个分类（狼系/猪系/熊系/蛇系/…/机关造物）+ 120+ 生物条目页
├── 05-地图/         地图总览 + 大地图 / 破风口 / 沉船 / 专属地图 / 特殊地图 + 30+ 地图条目页
├── 06-攻略/         新手指南 / 挑战攻略 / 进阶技巧
├── 07-收集/         成就系统 / 剧情图鉴与收集 / 账号资源系统
└── 08-附录/         资料来源
```

组织原则（与 Terraria Wiki 一致）：

- **叶子节点** = 具体物品 / 生物 / 地图 / 天赋 / 奇遇 / NPC 等元素，一个元素一个页面，页面内含「资料卡（infobox）+ 获取方式 + 数据 + 用途/备注 + 参见」；
- **枢纽节点（分类页）** = 只做罗列与跳转，由「卡片网格」链接到下级页面，不承载条目详情；
- **面包屑** 显示完整层级并可逐级返回；分类枢纽页与条目页均有页内目录（桌面右侧 / 窄屏顶部折叠目录）。

## 三、本地部署与使用

### 方式一：一键启动脚本（推荐）

双击项目根目录下的 **`启动Wiki.bat`**，脚本会自动完成：

1. 检测本机 Python 环境；
2. 在项目根目录启动本地 HTTP 服务器（默认 8000，被占用时自动顺延到下一个空闲端口）；
3. 自动打开浏览器并跳转到 `http://localhost:8000/app/`。

**停止服务**（任选其一）：

1. **关闭那个控制台窗口** —— 最直接，窗口一关，服务即停止；
2. **双击项目根目录下的 `停止Wiki.bat`** —— 适合窗口被最小化或找不到的情况，脚本会自动定位并结束服务进程；
3. 在服务窗口内按 `Ctrl + C`。

> 重复双击 `启动Wiki.bat` 时，若服务已在运行，脚本会直接打开浏览器，不会重复启动。

> 进阶用法（在项目根目录执行）：
>
> ```bash
> python app/tools/serve.py --port 9000     # 指定起始端口
> python app/tools/serve.py --no-browser    # 只启动服务，不打开浏览器
> python app/tools/serve.py --host 0.0.0.0  # 允许局域网内其它设备访问（手机 / 平板）
> python app/tools/serve.py --stop          # 停止服务（等价于「停止Wiki.bat」）
> ```

### 方式二：手动启动本地 HTTP 服务器

```bash
# 在项目根目录（GuDao_Wiki/）执行
python -m http.server 8000
# 浏览器访问 http://localhost:8000/app/
```

应用会自动读取 `wiki/manifest.json` 并并发加载全部页面（带加载进度），无需手动配置。

### 方式三：双击打开（Chrome / Edge）

打开 `app/index.html` → 点击「选择 wiki 文件夹」导入一次 → 内容缓存到 localStorage，之后可离线直开。

### 方式四：兼容模式导入（所有现代浏览器）

欢迎页点击「选择文件夹（兼容模式）」选择 `wiki` 文件夹即可。

> 提示：静态资源带 `?v=3` 版本参数，更新内容后无需担心旧缓存；若手动改动前端代码，可提升该版本号。

## 四、内容维护（重新生成）

内容以「生成器 + 手写文章」两种方式维护：

```bash
# 1. 编辑既有 wiki 页面或资料源（.temp_extract/ 下的提取文本）
# 2. 重新生成树状内容（会重建 03-物品 / 04-生物 / 05-地图 等分类与条目页）
python app/tools/generate_wiki.py
# 3. 更新页面清单
python app/tools/build_manifest.py
# 4. 校验（front matter / 死链 / 卡片链接 / 空页）
node app/tools/check_links.js
```

> 生成器以 `wiki/` 下的既有页面为数据源（物品图鉴、装备与武器、生物图鉴、地图与关卡等），
> 首次运行前请确保这些源页面存在（本仓库的 `.temp_extract/wiki_backup/` 保留了整理初期的原始版本，可用于回溯）。

## 六、常见问题

**Q1：双击打开后为何要手动选文件夹？**
浏览器安全策略禁止 `file://` 页面脚本读取本地文件。选择一次后即走本地缓存，可离线直开；或改用方式一 / 方式二（本地服务器）全自动加载。

**Q2：内容更新了但页面没变化？**
本地服务器方式（方式一 / 方式二）：点击顶部「同步」；其它方式：重新导入文件夹。仍无效时可在「帮助 → 清除本地内容缓存」后重试。

**Q3：缓存占多少空间？**
559 个页面的 Markdown 原文约 0.5 MB，localStorage 常见配额 5 MB，可放心使用；隐私模式下可能不可用（应用会降级为会话内可用）。

**Q4：为什么分类页本身没有详细数据？**
这是刻意的树状设计：分类页只负责罗列与导航，数据都在各条目页（避免同类物品挤在单页中）。

**Q5：本机一定要安装 Python 吗？**

- **用「启动Wiki.bat」（方式一）**：需要 Python 3。因为这个本地服务器就是用 Python 标准库
  `http.server` 实现的——只需 Python 3 本体，**不需要安装任何第三方包**，也无需联网。
- **不想安装 Python**：改用方式三 / 方式四——用 Chrome / Edge 直接打开 `app/index.html`，
  首次点击「选择 wiki 文件夹」导入一次即可，之后可离线使用，功能完全一致。

> 检查是否已装 Python：在任意命令行窗口输入 `python --version`，能显示版本号即可（需 3.7 及以上）。
